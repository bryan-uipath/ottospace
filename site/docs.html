ottospace docs

Install ottospace, set it up, and look up keys, tasks, settings and the ottospace ctl command. Inside the app, ⌘/ shows every key.

Quickstart

1Install

You need macOS 14 or later on Apple silicon.

$ curl -fsSL https://raw.githubusercontent.com/bryan-uipath/ottospace/main/install.sh | sh

The script installs two commands into ~/.local/bin. It needs no sudo, and it tells you if ~/.local/bin is not on your PATH.

  • osi, the ottospace installer.
  • ottospace, the latest build of main. There is no tagged release yet.

osi updates ottospace and switches between builds:

$ osi update           # install the newer build, if there is one
$ osi update --check   # only say whether there is one
$ osi current          # what is installed: channel, version, commit, date
$ osi rollback         # put the previous build back; again to undo
$ osi install pr 30    # a pull request's build; asks for one and waits. Needs gh
$ osi list             # builds you can install: main and open pull requests
$ osi uninstall        # remove ottospace and osi; settings and tasks are kept

A running ottospace keeps the build it started with. Quit it and start it again to use the new one.

What the checksum covers. Every download is checked against the SHA-256 published with it, and a failed check changes nothing. That catches a damaged download. It does not catch a compromised release: whoever can replace the build can replace its checksum. The install script and osi itself come from main over HTTPS with no checksum. A pull request build runs that pull request's code with your terminal's permissions: read the diff first.

To also get ottospace.app in ~/Applications, with a Dock icon:

$ curl -fsSL https://raw.githubusercontent.com/bryan-uipath/ottospace/main/install.sh | OTTOSPACE_APP=1 sh

To build from source instead, you need a Rust toolchain:

$ git clone https://github.com/bryan-uipath/ottospace
$ cd ottospace
$ cargo install --path crates/ottospace --bin ottospace

2Grant two permissions

Run ottospace from a terminal. It uses that terminal's permissions, so grant the terminal two, both in System Settings ▸ Privacy & Security:

  • Accessibility, to move app windows. ottospace does not start without it.
  • Screen & System Audio Recording, to show app windows in panes. macOS asks for it at launch, when ottospace lists the running apps.

You grant them once. Updates do not ask again.

Builds are not notarized. They are signed ad hoc. ottospace.app has its own identity, so macOS asks for both permissions for the app itself, and each build is a new identity: expect to grant both again after every update. That is why the bare command is the default. A zip downloaded in a browser is quarantined and macOS refuses to open the app; osi downloads with curl, which sets no such flag.

3Open a repository

ottospace opens on the Repos list: your repositories as headings, each checkout and worktree a row: its branch, and under it Default for the repository's own directory or the worktree's directory name. The + in the header adds a folder that is a repository or holds some. Click a row and a terminal opens in that directory. It fills the pane if the pane is empty; otherwise it splits to the right. Shift-click splits down.

Repos looks in ~/code and ~/notes. To change the folders, see Settings.

4Split

  • ⌘D splits right with a new terminal; ⌘⇧D splits down.
  • ⌘E (right) or ⌘⇧E (below) lets you pick what goes in the new pane: a terminal or an app. Type to filter: installed apps that are not running are offered too, and choosing one starts it.
  • ⌘T opens a new tab. Each tab has its own splits.
  • ⌘⌃← ⌘⌃→ ⌘⌃↑ ⌘⌃↓ move between panes. Past the edge they go on: left to the section list and the left rail, right to the conversation and the right rail. On a rail ↑ ↓ move, ↵ opens, Esc goes back.

A terminal pane runs your shell and closes when the shell exits.

5Host an app

Open Apps on the rail and click a running app. Its window moves into the focused pane if that is empty; otherwise into a split to the right. Shift-click splits down.

Below the running apps, "Not running" lists the apps you pinned, then the apps in your Dock (at most 12; "and N more" unfolds the rest). "All apps (N)" holds every other installed app: click the heading to unfold it, then click the filter or press / in list mode and type. A click on any of them starts the app in the background and puts its window in a pane. ottospace waits up to 30 seconds for the window.

Hover a row for its buttons: Pin keeps the app at the top, Hide stops a Dock app being suggested. Both are written to the apps and apps_hidden settings; the rest of the file stays as it is. For six seconds a line at the top offers to undo. The Dock is only read, never changed.

  • Scroll the app: the wheel or trackpad over its pane brings the window up (PEEK in the status bar) until the pointer leaves or you stop scrolling. The first scroll is lost.
  • Type in the app: click its pane. The status bar turns APP, and ottospace keys stop.
  • Come back: click ottospace itself (the rail, the top bar, another pane), or press the return key.
  • Give the window back to macOS: come back to ottospace, then ⌘W on the pane. The window returns to where it was.

The return key is F18, and it works while any app is in front. Most keyboards have no F18, so map Caps Lock to it. This lasts until you restart:

$ hidutil property --set '{"UserKeyMapping":[{"HIDKeyboardModifierMappingSrc":0x700000039,"HIDKeyboardModifierMappingDst":0x70000006D}]}'

After this, Caps Lock no longer toggles capitals, and any key mapping you had is replaced. To undo it: hidutil property --set '{"UserKeyMapping":[]}'. To use another key, start ottospace with OTTOSPACE_RETURN_KEY set to one of f13 to f20. The status bar names the key in use.

6Start a task

Press ⌘N: a new task opens in the drawer on the right. Type what needs doing and press ↵: its agent starts there at once, beside your workspace, which stays as it was. ⇧↵ files it for later. In the same line you can add:

  • #canvas to tag a project,
  • >canvas-app to name a repository or worktree from the Repos list,
  • @claude or @codex to say who works it, or a runner and a model: @claude-opus-5-5, @codex-gpt-6-astra,
  • p1 to p9 to set the priority.

Tab completes the tag being typed. Every tag is in the reference. The task appears in Tasks on the rail, and the status bar shows how many tasks need you.

Click a task, or press ↵ on it, for its conversation: its agent is started if it never ran, or its session gone on with. ⌘L moves the keyboard in and out of the drawer, ⌘⇧L closes it to the right rail, where each open conversation has a badge (⌘⌃1 … ⌘⌃9). Drag the drawer's left edge to resize it. Go to (⌘↵) in the drawer's header shows the task's tabs. With no @agent the default_agent setting says who starts, else claude.

Claude Code, drawn natively. The drawer drives Claude Code's structured mode and draws the reply as it streams: markdown, code blocks with a Copy button, tool calls as compact rows, a file edit's change as a diff card under its call (plain text, at most 40 lines), a working row while a turn runs, and Copy or Copy as Markdown on each message. Links open only on your click: web pages in your browser, files of the task's repository revealed in Finder; anything else is text, and nothing is fetched. Write in the composer: ↵ sends, ⇧↵ a new line, Esc Esc stops a turn. A permission request is a card: a allows this one request as shown, d denies it, m denies with your message, s shows all of a long one (needed before allowing it); ↵ does nothing there, and there is no "always allow". Chat | Terminal in the header switches to the CLI's own terminal and back on the same session. A session at work in another terminal is watched read-only: its calls and edits, a message at a time (Watching · updates per message in the header), with Take over once it is idle. Codex stays in a terminal. Text cannot be selected by dragging yet.

Tasks

The Tasks section is an inbox. It lists tasks in groups, in this order. In a group, priority decides (1 is most urgent), then age. Done is last and folded. Click a heading to fold it; in list mode a heading is a row, and ↵ or space folds it. A row shows what its session does now, while it works, and its model; hover it, or its badge on the right rail, for its card: state, tags, when it started, agent time, workspace, and tokens by model with how full its context is.

GroupHolds tasks in state
Needs youneeds_you, stale
Runningrunning, review
Latercaptured (the default), triaged, parked (on hold)
Donedone. cleaned tasks are not listed

By project. State | Project in the section's header (kept in the settings as tasks_view). Each #project is a group you can fold, with a small bar of its tasks' states (hover for the numbers), its open tasks, then a folded "Done · n"; tasks of no project come last. Under the list, Today says how many tasks were done today, how many run, and how long agents worked. A task keeps its time and its tokens (no prices) in its file, so they stay when the session files go.

  • Snooze hides a task for one hour. Dismiss removes it from the list. Either comes back when the task moves under Needs you.
  • Hold moves the task to On hold. Undo takes back the last snooze, hold or dismiss.
  • Other sessions. Below the tasks, folded at first (a click on its heading unfolds it), the section lists the Claude Code and Codex sessions of your listed repositories that are no task's, such as one you started by hand in a terminal: the runner, the repository, the session's title (the one Claude Code or Codex keeps, when there is one), active or idle, what it does now, when it was last active, and the model. A switch on its heading, Today | 7 days | 30 days | All (kept in the settings as sessions_range), picks how far back it lists; one at work is always listed. A click on a row opens its conversation in the drawer, with no task: an idle session is gone on with there, in the folder it started in; one at work in another terminal is not, and the drawer says so. Adopt makes a task of one, with its repository and runner set, and its conversation is the task's; the task then follows the session (Running while it works, Needs you once when it has been quiet for 3 minutes), with the Tasks section open or closed, until you or an agent set its state. Hide removes it until the next start. ottospace reads the runners' session files (every 5 seconds while the section is open), and never types into a session or signals it; only your click or Adopt starts the runner's own resume command.
  • A click on a row opens its conversation. Hover a row for buttons: snooze, hold, dismiss. After a snooze, hold or dismiss by mouse, a line at the top of the section offers Undo for 6 seconds.
  • Task groups. Every tab is on the one bar. A task's tabs sit side by side behind its badge (its two letters, bordered in its own colour, its state as a dot) and are underlined in its colour; the tabs of no task come last. The same badge is on its panes, its row, the right rail and the drawer. ⌘1 … ⌘9 and tab cycling count every tab.
  • Starting a task takes the tab on show if it is no task's; nothing else moves. ⌘T joins the task on show; New Tab outside the Task (palette) does not. Drag a tab onto another group to move it there; Remove Tab from Task unlinks it; Move Tab to Task… (palette) lists the tasks to move it to; Claim tab on a row gives the tab on show to that task.
  • Selecting a task's tab shows its conversation in the open drawer. A click on a task, the rail or ⌘⇧N shows a conversation and leaves the tab on show; Go to its tabs (⌘↵) in the drawer goes there.
  • Closing a task's tabs does not end the task. Dismissing it unlinks its tabs (they stay open) and takes it off the rail; Undo links them again.
  • Tasks are kept in ~/.ottospace/tasks, one JSON file each, or in the folder the tasks setting names. Change tasks in the app or with ottospace ctl, not by editing the files.

  • A tag counts only if its name is known. A >word, @word or $word that names nothing stays in the title where it was typed, and so does a /word that is not a file or directory. ask @ana, costs $5 and use > 3 workers are safe. A name starts with a letter, so #123, >3 and $5 are never tags. #project always counts: a new name is a new project.
  • A /path is under the home folder (~/notes.md), or, when the line names a >repo, inside that repository: /src/export with >canvas-app is src/export in it. If nothing is there, or no repository is named, it is absolute: /Users/me/notes.md. The repository is looked in first, then the root of the disk. The task keeps the word as typed and, beside it, the absolute path that was found.
  • Punctuation and spaces. A comma or full stop after a tag is not part of it. A space in a path or a reference is written with a backslash before it, ~/My\ Notes, and so is a backslash itself; taking a row, a drop or ⌥-click writes them for you. A reference's file entry keeps its kind, name, id and app only: not a window's title or a directory.
  • Skills are the folders with a SKILL.md in ~/.claude/skills, $CLAUDE_CONFIG_DIR/skills, ~/.codex/skills (or $CODEX_HOME/skills) and the .claude/skills of the task's >repo. OTTOSPACE_SKILLS (directories, : between them) replaces the runners' folders.
  • How many. One #project, one >repo, one @agent, one priority: of two, the last one counts. Every /path and $skill is kept, each once (at most 20 of each).
  • A runner and a model. @claude-opus-5-5 is Claude Code with the model claude-opus-5-5; @codex-gpt-6-astra is Codex with gpt-6-astra. The dropdown offers the built-in models, or those the agent_models setting names; a word of the name finds a row (@opus). A model that is not listed works by typing it: any @claude-<name> or @codex-<name> is a runner and a model. A saved agent whose file is named as a runner, or claude-… or codex-…, is not offered: the name means the runner or its model.
  • What they do today. #project and >repo are used: the home screen groups by project, and a task opens a terminal in its repository. @agent says which agent starts in the drawer. /path and $skill are stored on the task and shown on its row; nothing loads a skill yet.
  • @name named a repository before. It does not now.

Settings

ottospace reads ~/.ottospace/settings.json at start. Every key is optional.

Open Settings (⌘,, the palette, or ottospace ▸ Open Settings) opens the file in a tab titled Settings, whose terminal runs $VISUAL, else $EDITOR, else vi, as your login shell sets them (an editor that must wait, as code -w, needs its flag). A file that is not there is made {} first. Again while that tab is open brings it forward; quitting the editor closes its pane. Only you open it.

A change is read when the file is saved: what is wrong in it is said in the status bar (settings.json:3:1 trailing comma, or the first of several and how many more) and the last good settings stay, until it is right again. Then windows, capture, wheel_to_apps, workbook_scrollback_lines, default_agent, conversation_view, session_quiet_minutes, tasks_view, sessions_range, calendar_notify and calendar_notify_for apply at once; any other key changed says “restart to apply” with its name (repos, apps and apps_hidden only when changed by hand: the app's own writes are already applied). Removing the file goes back to the defaults.

Drive it from a shell

ottospace ctl sends one JSON request to the running app and prints one JSON reply. You, a script or a coding agent can use it. It talks to a Unix socket that only your user can open (mode 0600).

$ ottospace ctl '{"cmd":"state"}'   # everything, as JSON
Exit statusMeaning
0The request was understood. The reply is usually the full state after it
1The request was refused ({"ok":false,"error":".."}), or no ottospace is running
2ottospace was called wrongly

Unknown commands and unknown fields are refused. Exit 0 does not prove the change happened: a request that names a pane or tab that is gone is ignored without an error, and so are most requests while the picker or the key reference is open. Read the reply.

Run a command in a new pane and read its output

$ ottospace ctl '{"cmd":"split","axis":"down"}'   # reply: state.focused is the new pane, say 3
$ ottospace ctl '{"cmd":"type","pane":3,"text":"cargo test; echo done-7f3a-$?\r"}'
$ ottospace ctl '{"cmd":"wait","pane":3,"pattern":"^done-7f3a-[0-9]+$","timeout_ms":600000}'
$ ottospace ctl '{"cmd":"capture","pane":3,"history":true}'

7f3a is a token made up for this run, so wait does not match older output. The number after it is the command's exit status. A shell started by ottospace has $OTTOSPACE_PANE and $OTTOSPACE_TAB.

Tasks

$ ottospace ctl '{"cmd":"task_new","line":"fix zoom flicker #canvas >canvas-app @claude p1"}'
$ ottospace ctl '{"cmd":"task_add","title":"Review the retry fix","priority":1,"state":"needs_you"}'
$ ottospace ctl '{"cmd":"task_set_state","id":1,"state":"needs_you"}'   # running, needs_you, done, ...
$ ottospace ctl '{"cmd":"task_list"}'
$ ottospace ctl '{"cmd":"task_pop"}'   # go to the tabs of the first task that needs you
$ ottospace ctl '{"cmd":"task_open","id":1}'   # go to the tab of task 1 shown last

An agent reports its own state: running while it works, needs_you when it waits for you. That is what moves a task to the top of the inbox. Only you link a tab to a task: an agent's task has no tab until you give it one.

The full guide, and a skill for coding agents

ottospace skill prints every request with an example, what the state fields mean, and rules for using them safely. It always matches the installed version. To make it a Claude Code skill:

$ mkdir -p ~/.claude/skills/ottospace
$ ottospace skill --stub > ~/.claude/skills/ottospace/SKILL.md

Treat the socket like a shell. type sends keys to a terminal, so it can run anything you can. Every state reply includes the visible text of every terminal pane. Let an agent use it only as you would let it use your shell.

How app windows are hosted

macOS cannot move another app's window inside ottospace's own window. ottospace does the next best thing:

  1. The window is parked. An app window that is not in use sits off-screen, with one pixel on a display. ottospace moves it with the Accessibility API.
  2. The pane shows a live stream. ScreenCaptureKit streams the parked window into its pane.
  3. A click brings the real window. Click the pane and the real window moves over it, and the click is replayed. Input is native from then on.

This is why ottospace needs Accessibility and Screen Recording. A new window of a hosted app gets its own pane. The original window positions are saved to disk and restored on every way out: a quit, a signal, and after a crash or kill -9 a small guardian process puts them back. A window lost off screen comes back with ottospace rescue in a terminal, or Developer ▸ Bring All Windows Back. The badge on an app in the Apps list is how many windows it has open.

Known limits

  • Quitting ends what runs in terminals. Tabs, splits and folders come back, with each terminal's last lines and the command offered on its prompt, not the program. An app that is not running is not started: its pane offers Open <App>.
  • Filing a task starts nothing: no agent and no worktree. The task gets its first tab when you open it.
  • A running app cannot be pinned from the Apps section: pin it while it is closed, or name it in apps.
  • While an app has the keyboard, ottospace keys do not fire. Use the return key.
  • Opened from Finder or the Dock (ottospace.app), terminal panes start in /, not your home directory.
